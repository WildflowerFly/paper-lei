## 1. 使用方式与完成定义

### 1.1 标记规则

- `[ ]`：待开发或未通过验收；只有满足任务验收条件并记录证据后才改为 `[x]`。
- **P0**：数据安全、架构前置或核心链路；优先实施，未完成阻断后续阶段或发布。
- **P1**：V1.0 必需能力；允许在核心链路完成后实施，仍是首版发布条件。
- **S / M / L**：约 0.5–1 / 1–3 / 3–5 人日的初步工作量，包含开发和局部验证，不包含外部等待。超过 L 的任务应拆分后实施；估算不是工期承诺。
- 依赖使用任务 ID；只列直接前置，不重复全部间接依赖。后续发现依赖需同步更新。
- 每项提交/PR 关联任务 ID，并记录测试命令、测试环境、结果和截图/日志位置。当前清单中的路径是计划产物，不能视为已经存在。

优先级只决定执行顺序，不用于删减 V1.0 功能。本文不安排具体人员和日期，待技术原型、人员投入与估算校准后形成迭代排期。

### 1.2 通用完成定义（DoD）

1. 功能符合 PRD、UI/UX 与 TDD，正常、空、加载、失败、取消状态完整。
2. 类型、格式、lint 和受影响测试通过；文件保存、安全、路径、渲染等关键逻辑有有效测试，不以仅验证实现细节的测试充数。
3. 无文档内容丢失、静默覆盖、路径越权或未经授权的脚本执行。
4. 文档界面使用统一黑白灰变量，正文符合 GitHub 风格；涉及 UI 的任务附浅色/深色结果。
5. 键盘入口、焦点、中文输入法和用户错误提示符合设计；异常不只写在控制台。
6. 若改变接口、默认值、版本范围或安全边界，同步更新两份设计文档及受影响任务。

## 2. 阶段与交付门槛

| 阶段 | 目标 | 交付门槛 |
| --- | --- | --- |
| M0：工程与风险验证 | 建立工程，验证 Windows 和安全方案 | 可运行窗口；保存竞态、PDF/打印、渲染隔离原型有结论 |
| M1：基础界面 | 完整可操作的黑白灰桌面框架 | 正确左右布局、主题、导航、标签、状态和键盘基础 |
| M2：编辑预览闭环 | 源码输入、基础渲染与双向定位 | 输入流畅；GitHub 风格正文；定位和滚动有内容映射 |
| M3：可靠文件系统 | 真实文件生命周期与多文档 | 打开、保存、冲突、回收站、恢复可验证，无静默覆盖 |
| M4：完整 Markdown 与资源 | 代码、公式、图表、图片、HTML | 扩展语法和资源管理可靠，恶意输入不能突破边界 |
| M5：效率与阅读 | 目录、搜索、设置、模式 | 从打开到查找、阅读、编辑形成完整工作流 |
| M6：导出和打印 | 统一快照输出 HTML/PDF | 文件可独立打开；样式可读；取消和错误可处理 |

PRD 的七个开发阶段保留核心顺序；本清单将早期风险验证和最终发行验收明确列出，并将安全、性能和基础恢复提前到相关功能阶段。
