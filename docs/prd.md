# Markdown Studio 产品需求文档（PRD）

**文档版本：** V1.0  
**产品名称：** Markdown Studio  
**产品类型：** Windows 桌面 Markdown 编辑与阅读软件  
**目标平台：** Windows 10 / Windows 11  
**文档状态：** 初始开发需求基线

---

# 1. 产品概述

## 1.1 产品背景

Markdown 是一种轻量级标记语言，具有语法简单、可读性强、跨平台兼容性好等特点，被广泛应用于技术文档、个人笔记、项目说明、知识整理和软件开发等领域。

目前市面上的 Markdown 编辑软件虽然具备较为完善的编辑与阅读能力，但不同产品在界面设计、操作体验、文件管理和功能复杂度方面存在差异。

本项目计划开发一款名为 Markdown Studio 的 Windows 桌面应用，为用户提供简洁、高效、直观的 Markdown 文档编辑和阅读体验。

软件以 Typora 为主要产品参考对象，采用左右分屏的交互形式，将 Markdown 源码编辑与实时渲染预览结合起来，使用户能够在编写 Markdown 内容的同时查看最终排版效果。

## 1.2 产品定位

Markdown Studio 是一款以本地文件为核心的 Markdown 编辑与阅读工具。

主要定位如下：

1. 提供完整的 Markdown 源码编辑能力。
    
2. 提供实时 Markdown 渲染预览。
    
3. 提供本地 Markdown 文件及文件夹管理能力。
    
4. 支持常见 Markdown 扩展语法。
    
5. 提供舒适、简洁、可定制的阅读体验。
    
6. 支持文档搜索、导出和快捷操作。
    

## 1.3 产品设计原则

### 本地优先

所有 Markdown 文档直接保存在用户指定的本地目录中，软件不强制使用专有文档格式。

### 实时预览

用户在源码编辑区域输入内容后，预览区域自动更新渲染结果。

### 双向辅助

用户既可以在源码区域编辑文档，也可以通过预览区域定位对应源码。

### 简洁易用

采用清晰的功能分区，减少不必要的操作和复杂界面。

### 模块化设计

各功能模块保持相对独立，便于后续增加编辑模式、扩展语法和其他功能。

# 2. 用户与使用场景

## 2.1 目标用户

主要面向以下用户群体：

- 需要编写技术文档的软件开发人员。
    
- 需要整理学习笔记的学生。
    
- 需要管理 Markdown 文档的个人用户。
    
- 需要阅读和修改 GitHub 项目文档的开发者。
    
- 需要使用 Markdown 进行知识管理的用户。
    

## 2.2 核心使用场景

### 场景一：打开并阅读 Markdown 文件

用户通过文件选择窗口打开本地 Markdown 文件，软件读取文件内容，并在预览区域展示排版后的结果。

### 场景二：编辑 Markdown 文档

用户在右侧源码编辑器中编写 Markdown 内容，左侧预览区域实时展示渲染结果。

### 场景三：管理 Markdown 文件夹

用户打开一个文件夹作为工作空间，在左侧文件导航栏中浏览、创建、重命名和删除文件。

### 场景四：阅读长篇技术文档

用户通过文档目录快速定位章节，并使用搜索功能查找文档中的内容。

### 场景五：导出文档

用户将 Markdown 文件导出为 PDF 或 HTML 文件，以便分享、打印和归档。

# 3. 产品整体界面设计

## 3.1 主界面布局

软件采用经典的多区域桌面布局。

整体分为四个主要区域：

1. 左侧文件导航栏。
    
2. 中央左侧 Markdown 实时预览区域。
    
3. 中央右侧 Markdown 源码编辑区域。
    
4. 底部状态栏。
    

顶部另外设置应用菜单栏和工具栏。

## 3.2 界面区域说明

### 3.2.1 顶部菜单栏

包含以下菜单：

- 文件
    
- 编辑
    
- 视图
    
- 格式
    
- 工具
    
- 帮助
    

菜单中的操作应提供对应的快捷键，并根据当前文档状态决定是否可用。

### 3.2.2 左侧文件导航栏

负责显示和管理用户打开的文件及文件夹。

主要内容：

- 工作空间名称。
    
- 文件夹树。
    
- Markdown 文件列表。
    
- 文件夹展开和折叠。
    
- 文件创建和删除入口。
    
- 最近打开文件入口。
    
- 收藏文件入口。
    

支持调整侧边栏宽度和隐藏侧边栏。

### 3.2.3 中央左侧：实时预览区域

负责将 Markdown 源码转换为可阅读的排版效果。

支持：

- 标题。
    
- 段落。
    
- 粗体和斜体。
    
- 删除线。
    
- 有序列表和无序列表。
    
- 任务列表。
    
- 引用块。
    
- 代码块。
    
- 表格。
    
- 图片。
    
- 超链接。
    
- 数学公式。
    
- Mermaid 图表。
    
- 脚注。
    

预览区域应保持适当的阅读宽度，并支持独立滚动。

### 3.2.4 中央右侧：源码编辑区域

使用 CodeMirror 6 实现 Markdown 源码编辑。

支持：

- Markdown 语法高亮。
    
- 行号显示。
    
- 自动缩进。
    
- 代码折叠。
    
- 搜索和替换。
    
- 撤销和重做。
    
- 多种快捷键。
    
- 光标位置显示。
    
- 当前文档修改状态。
    

编辑区域应支持独立滚动，并与预览区域保持适当的滚动同步。

### 3.2.5 底部状态栏

显示当前文档的基本信息：

- 文档名称。
    
- 文档保存状态。
    
- 字数统计。
    
- 字符数统计。
    
- 当前光标行号。
    
- 当前光标列号。
    
- 当前编辑模式。

# 4. 功能需求

## 4.1 文件管理模块

### 4.1.1 打开单个文件

用户可以通过文件选择对话框打开本地 Markdown 文件。

需求：

- 支持打开 `.md` 文件。
    
- 支持打开 `.markdown` 文件。
    
- 支持通过系统文件关联打开文档。
    
- 支持拖拽文件进入软件。
    
- 打开文件后自动读取文本内容。
    
- 打开失败时提供错误提示。
    

### 4.1.2 打开文件夹

用户可以选择一个本地文件夹作为工作空间。

打开后：

- 自动扫描文件夹中的文件。
    
- 以树形结构展示目录。
    
- 支持展开和折叠文件夹。
    
- 支持点击 Markdown 文件打开文档。
    
- 支持刷新文件列表。
    

### 4.1.3 新建文件

用户可以在当前工作空间中创建新的 Markdown 文件。

要求：

- 支持指定文件名称。
    
- 默认扩展名为 `.md`。
    
- 创建后自动打开。
    
- 文件名重复时提示用户。
    

### 4.1.4 新建文件夹

用户可以在工作空间内创建文件夹。

要求：

- 支持指定文件夹名称。
    
- 支持在当前目录下创建。
    
- 文件夹创建成功后刷新文件树。
    

### 4.1.5 重命名文件

用户可以重命名文件或文件夹。

要求：

- 修改后同步更新文件树。
    
- 已打开文件的路径信息同步更新。
    
- 避免覆盖同名文件。
    

### 4.1.6 删除文件

支持删除文件和文件夹。

要求：

- 删除前进行二次确认。
    
- 文件夹删除前提示可能包含的文件数量。
    
- 默认使用系统回收站机制，避免直接永久删除。
    
- 删除正在编辑的文档时，需要先处理未保存内容。
    

### 4.1.7 最近打开

记录用户最近打开的 Markdown 文件。

要求：

- 按最近使用时间排序。
    
- 支持重新打开。
    
- 支持清除历史记录。
    
- 文件不存在时提示用户。
    

### 4.1.8 收藏文件

用户可以收藏常用 Markdown 文件。

要求：

- 支持添加和取消收藏。
    
- 收藏列表独立展示。
    
- 应用重启后保留收藏状态。
    

### 4.1.9 多标签页

支持同时打开多个 Markdown 文档。

要求：

- 每个文件对应一个标签。
    
- 点击标签切换文档。
    
- 支持关闭标签。
    
- 未保存文档显示修改标识。
    
- 关闭未保存文档时提示保存、放弃或取消。

## 4.2 Markdown 编辑模块

### 4.2.1 实时源码编辑

用户在源码编辑区域输入内容后，系统自动更新 Markdown 文档内容。

要求：

- 支持标准 Markdown 语法。
    
- 支持常见扩展语法。
    
- 编辑内容实时同步到预览区域。
    
- 不需要手动点击预览按钮。
    
- 输入过程中不应出现明显卡顿。
    

### 4.2.2 Markdown 语法高亮

根据 Markdown 语法结构对源码进行区分显示。

支持：

- 标题。
    
- 强调语法。
    
- 列表标记。
    
- 引用标记。
    
- 链接。
    
- 图片。
    
- 代码块。
    
- 表格。
    
- HTML 标签。
    

### 4.2.3 撤销与重做

支持编辑操作撤销和重做。

要求：

- 支持快捷键。
    
- 保持合理的撤销历史。
    
- 文件切换时维护各文档独立的编辑状态。
    

### 4.2.4 搜索和替换

支持在当前 Markdown 文档中搜索内容。

要求：

- 支持关键词搜索。
    
- 高亮搜索结果。
    
- 支持上一个和下一个结果。
    
- 支持替换当前结果。
    
- 支持全部替换。
    

### 4.2.5 自动保存

采用防抖机制自动保存。

建议默认等待用户停止输入 800ms 后执行保存。

要求：

- 只保存发生变化的文档。
    
- 保存成功后更新状态栏。
    
- 保存失败时显示错误信息。
    
- 支持手动保存。
    
- 关闭窗口前检查未保存文档。
    
- 避免多个保存任务同时覆盖同一文件。
    

### 4.2.6 源码编辑设置

支持配置：

- 编辑器字体。
    
- 字体大小。
    
- 行高。
    
- 行号显示。
    
- 自动换行。
    
- 制表符宽度。
    
- 当前行高亮。
    
- 编辑器主题。

## 4.3 Markdown 实时渲染模块

### 4.3.1 标准 Markdown

支持：

- 一级至六级标题。
    
- 段落。
    
- 粗体。
    
- 斜体。
    
- 删除线。
    
- 分隔线。
    
- 有序列表。
    
- 无序列表。
    
- 引用。
    
- 行内代码。
    
- 代码块。
    
- 链接。
    
- 图片。
    

### 4.3.2 GitHub Flavored Markdown

支持常见 GFM 扩展：

- 任务列表。
    
- 表格。
    
- 删除线。
    
- 自动链接。
    
- 代码块语言标识。
    

### 4.3.3 代码块渲染

使用 Shiki 实现代码语法高亮。

要求：

- 支持常见编程语言。
    
- 支持多种代码主题。
    
- 显示代码语言。
    
- 提供代码复制按钮。
    
- 未知语言时提供普通文本显示。
    

### 4.3.4 数学公式

使用 KaTeX 渲染 LaTeX 数学公式。

支持：

- 行内公式。
    
- 独立公式。
    
- 常见数学符号。
    
- 矩阵。
    
- 分数。
    
- 上下标。
    

公式渲染失败时应提供合理的错误展示，不能影响整个文档的正常阅读。

### 4.3.5 Mermaid 图表

支持 Mermaid 图表语法。

包括：

- 流程图。
    
- 时序图。
    
- 类图。
    
- 状态图。
    
- 甘特图。
    
- 饼图。
    

要求：

- 自动识别 Mermaid 代码块。
    
- 渲染为图形。
    
- 支持错误提示。
    
- 支持适当的缩放和查看。
    

### 4.3.6 HTML 内容

支持 Markdown 文件中的常见 HTML 内容。

要求：

- 对不安全 HTML 进行过滤。
    
- 控制脚本执行。
    
- 限制危险资源访问。
    
- 保证普通 HTML 内容能够正常展示。

## 4.4 图片和附件管理模块

### 4.4.1 图片展示

支持：

- 本地相对路径图片。
    
- 本地绝对路径图片。
    
- 网络图片。
    
- PNG、JPG、JPEG、GIF、SVG、WebP 等常见格式。
    

### 4.4.2 相对路径处理

以当前 Markdown 文件所在目录为相对路径解析基准。

例如：

```
Project/
├── README.md
└── images/
    └── cover.png
```

Markdown：

```
![封面](./images/cover.png)
```

要求：

- 正确解析相对路径。
    
- 文件移动后重新计算资源路径。
    
- 图片不存在时提供占位提示。
    
- 不应将应用安装目录错误地作为图片路径基准。
    

### 4.4.3 图片插入

支持将图片拖入源码编辑区域。

建议提供两种方式：

- 引用图片原始路径。
    
- 将图片复制到用户指定的资源目录后引用相对路径。
    

插入操作应遵循用户选择，不能未经授权移动或删除原图片。

### 4.4.4 图片查看

支持点击预览图片进入大图查看。

建议支持：

- 放大。
    
- 缩小。
    
- 适应窗口。
    
- 原始尺寸。
    
- 关闭查看。

# 5. 交互与操作需求

## 5.1 双栏同步机制

左右区域是软件的核心交互功能。

### 源码到预览

用户修改右侧源码后：

1. 获取当前 Markdown 文本。
    
2. 对文本进行解析。
    
3. 生成渲染内容。
    
4. 更新左侧预览。
    
5. 保持合理的滚动位置。
    

### 预览到源码

用户点击左侧预览内容时：

1. 获取点击元素对应的源码位置。
    
2. 将右侧编辑器定位到对应位置。
    
3. 设置源码光标或选区。
    
4. 必要时滚动编辑器，使对应代码可见。
    

对于无法准确映射源码位置的复杂节点，应采用尽可能接近的定位方式，不得随意修改文档内容。

## 5.2 滚动同步

支持左右区域滚动位置同步。

要求：

- 用户滚动一侧时，另一侧尽可能同步到对应内容。
    
- 不能简单地只按照滚动百分比同步。
    
- 对于长文档，应尽量基于段落或标题位置映射。
    
- 避免同步事件相互触发造成滚动抖动。
    

## 5.3 快捷键

建议默认快捷键：

|操作|快捷键|
|---|---|
|新建文件|Ctrl + N|
|打开文件|Ctrl + O|
|保存|Ctrl + S|
|全部保存|Ctrl + Shift + S|
|查找|Ctrl + F|
|替换|Ctrl + H|
|撤销|Ctrl + Z|
|重做|Ctrl + Y|
|切换侧边栏|Ctrl + B|
|全屏|F11|
|关闭标签|Ctrl + W|

快捷键应允许后续自定义，并避免与系统快捷键冲突。

# 6. 数据管理需求

## 6.1 核心数据存储

Markdown Studio 采用本地文件直接读写方式。

文档以用户原始 `.md` 文件为最终存储载体。

软件不得要求用户将文档导入专有数据库才能编辑。

## 6.2 辅助数据

软件可以在本地应用配置目录保存：

- 最近打开文件。
    
- 收藏文件。
    
- 窗口大小和位置。
    
- 编辑器设置。
    
- 主题设置。
    
- 工作空间记录。
    
- 最近阅读位置。
    

初期采用 JSON 保存辅助信息即可，后期根据数据规模考虑引入 SQLite。

## 6.3 文件冲突处理

当软件检测到外部程序修改了当前正在编辑的文件时：

- 检测文件修改时间和内容状态。
    
- 不允许直接覆盖外部修改。
    
- 提示用户文件已经发生变化。
    
- 提供重新加载、保留当前内容和对比处理等选择。
    

需要防止自动保存覆盖用户在其他编辑器中的修改。

## 6.4 文件编码

建议：

- 默认使用 UTF-8。
    
- 读取时识别 UTF-8 BOM。
    
- 尽可能保留原文件换行符格式。
    
- 避免无意义地改变文件编码和换行格式。

# 7. 非功能需求

## 7.1 性能要求

建议初期验收目标：

- 软件正常启动时间控制在合理范围内。
    
- 普通 Markdown 文件打开后快速显示。
    
- 编辑后预览能够及时更新。
    
- 文件树支持较大数量的文件。
    
- 长文档不能出现明显的输入阻塞。
    
- 图片和图表采用必要的延迟加载机制。
    

建议使用 1MB、5MB 和 10MB 的测试文档进行性能测试，具体表现根据实际机器配置评估。

## 7.2 稳定性

- 编辑过程中不应因为预览渲染失败导致软件崩溃。
    
- 单个公式或 Mermaid 图表错误不能影响其他内容。
    
- 文件读取失败应提供明确错误信息。
    
- 自动保存失败应保留编辑器中的内容。
    
- 异常关闭后尽可能提供恢复机制。
    

## 7.3 安全性

- 不执行 Markdown 中未经授权的脚本。
    
- 对 HTML 内容进行安全过滤。
    
- 对本地文件访问进行权限限制。
    
- 不允许通过路径构造随意访问受限目录。
    
- 外部网络资源加载应可控制。
    
- 不收集或上传用户本地文档内容。
    

## 7.4 可维护性

- 采用模块化代码结构。
    
- 编辑器功能采用扩展机制。
    
- 文件系统操作统一封装。
    
- 业务逻辑与 UI 组件分离。
    
- 关键模块提供单元测试。
    
- 使用 Git 管理项目版本。

## 8.2 桌面应用技术

|技术|用途|
|---|---|
|Tauri 2|桌面应用框架|
|Rust|系统服务|
|Tauri Plugin FS|文件系统操作|
|Tauri Plugin Dialog|文件选择对话框|
|Tauri Plugin Store|辅助配置持久化|
|Tauri Plugin Opener|外部链接打开|

## 8.3 整体架构

采用分层模块化架构：

- 界面层：负责窗口布局和用户交互。
    
- 业务层：负责文档管理、自动保存和搜索。
    
- 编辑器层：负责源码编辑和 Markdown 渲染。
    
- 系统层：负责本地文件及系统能力。
    
- 数据层：负责 Markdown 原文件和辅助配置。
    

前端通过 Tauri IPC 调用 Rust 系统能力。

# 14. 产品成功标准

Markdown Studio 第一版应达到以下目标：

1. 用户可以方便地打开和管理本地 Markdown 文件。
    
2. 用户可以在右侧编辑源码，并在左侧实时查看渲染效果。
    
3. 软件能够正确处理常见 Markdown 语法和扩展内容。
    
4. 用户修改的文档能够可靠地保存到原始文件。
    
5. 文件管理、搜索、目录和导出等功能能够形成完整工作流。
    
6. 软件运行稳定，界面简洁，操作流畅。
    

**最终目标：打造一款轻量、稳定、易用、以本地文件为核心的 Windows Markdown 编辑与阅读软件。**
